# v0.3.12 (versionCode 45) — regression report

Required by `CLAUDE.md` rule 3. All runs are adb-driven, which keeps MainActivity in
the foreground so the remount genuinely happens — see the note on the on-device flow
at the end, which cannot verify correctness at all.

Build under test: commit `4120652` (reports carry `build: … commit 4120652`, no
`-dirty`).

## Correctness

Eleven cases, each judged **after a proven unmount/remount** (`remountAndProve`
requires the mount list to empty and the drive identity to change):

`unaligned` A (sector tail), B (truncate+rewrite) · `correct` A (neighbour
integrity), A (victim tail), B (unaligned offset+length), C (100 odd-sized appends),
D (recycled clusters), E (slack leak + read past EOF), F (read-only writes nothing),
G (2 GiB file probes at 0, mid, the 2 GiB boundary and EOF)

|---|---|---|
| Huawei P20 Lite | exFAT | ALL PASSED |
| Huawei P20 Lite | FAT32 | ALL PASSED, both cache arms |
| Samsung M30 | exFAT | ALL PASSED |
| OnePlus 7 | FAT32 | ALL PASSED |

Case B produced SHA-256 `ac3e360a187bfe9f…` in **every** run on **every** device,
across both filesystems — independent evidence the byte-level results agree rather
than each device merely agreeing with itself.

In the cache-off arm, case F reports `skipped (no cache in the stack)`: it detects
unwanted writes through the cache's device-write counter, which does not exist when
the cache is absent. A skip rather than a false pass.

## Fixes covered

Thirteen correctness fixes, seven of them silent data corruption. Each was reproduced
on hardware before being fixed, with a test that fails on the old code:

| Fix | Evidence |
|---|---|
| V1 trailing-sector zero-fill | pre-fix: a 10-byte write zeroed 502 bytes |
| V2 stale `entry.startCluster` | pre-fix: read back freed content; entry claimed 178 MB for a 2 KiB file |
| V3 cluster slack leak | pre-fix: 4096-byte read of a 100-byte file returned the freed `0xDD` marker |
| V4 read-only close rewrote the directory | pre-fix: 8 blocks (32 KiB) written for a read-only open |
| V5 `array()` on direct buffers | build + suite |
| V6 one SCSI command per cluster | throughput went from flat across buffer sizes to scaling with them |
| V7 corrupt directory OOM | 32 MiB bound; 10,000-entry directories still list |
| exFAT `node.size` desync | correctness case C |
| exFAT swallowed `-1` reads | inspection only — needs induced I/O failure |
| exFAT short writes | inspection only |
| exFAT listing failure shown as empty | 20,000 entries listed, 100 files opened |
| Use-after-unmount SIGSEGV | no crash since; `0x6c` fault offset identified `ef->sb == NULL` |
| I/O after block-device close | unit-tested; post-close write reaches no sector |
| Key material left on the C++ stack | drives still unlock, so wiping does not break header decryption |
| `finalize()` doing USB I/O | pre-fix: `FinalizerWatchdogDaemon` timeout on the Huawei; post-fix: 0 FATAL lines |
| `onDestroy` closing live USB connections | pre-fix: run died at the block layer; post-fix: completes |

## Known limitations of this report

- **`fixtures` reports "nothing to check" on every device.** It is the only check with
  an external ground truth — SHA-256 values computed on a host — and the drives still
  carry manifests with `-` placeholders. Nothing has yet compared a host-computed hash.
- **Serpent is untested.** It is a supported cipher; every run here used AES/SHA-512.
- **Multi-drive is untested.** The `drive` selector, the `driveTag` collision
  detection and cross-drive SAF concurrency all need two drives on one phone.
- **Two exFAT fixes rest on inspection**, not measurement: the swallowed `-1` read and
  the short-write loop. Both need an induced I/O failure to exercise.
- **The on-device (no-adb) flow cannot verify correctness.** Android destroys the
  backgrounded MainActivity, which nulls the mount handlers, so no remount can happen.
  Those runs report `NOT VERIFIED` with the reason rather than a pass. This is
  structural until mounts move out of the activity.
- **This is a debug build.** Release builds contain no benchmark harness at all
  (verified absent from the release APK's dex, manifest and native library), so the
  artefact tested here is not byte-identical to the one shipped. The app code under
  test is the same.
