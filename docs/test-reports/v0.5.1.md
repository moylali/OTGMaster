# v0.5.1 (versionCode 50): regression report

`AGENTS.md` commit rule 3 asks for at least four devices. **The owner waived that for this tag
only** ("Only 1 device testing is needed"): customers on 0.5.0 were hitting the LUKS2 unlock
regression this release fixes. One phone, the Pixel 7 Pro, ran all five matrix drives, and **the
bigwrite section was left out** to save time, so no run here exercises large writes. Every run is
recorded in full in [`../BENCHMARK_RUNS.md`](../BENCHMARK_RUNS.md) ("2026-11-09: 0.5.1 on the
Pixel 7 Pro, without bigwrite"), and every figure here comes from there.

## Build under test

Every report is stamped `build: 0.5.1 (50) commit 27a958e`, a debug build. `27a958e` is PR #134's
head, and it landed on `main` as `10da2b4` with the same files. The tagged tree differs from it
only in docs, records and store screenshots.

What the release adds since v0.5.0: VeraCrypt hidden volumes with hidden volume protection; Eject,
which unmounts a whole drive and hands it back to Android; a USB access setting; a setting that
hides the backup UI; one slider and a centred form on tablets in landscape; and the LUKS2 fix,
where Argon2 runs a key slot's lanes on threads again.

## What every run checks

free, block, dir, path, seq, random, opens, write verify, unaligned, correctness and fixtures, as
in [`v0.5.0.md`](v0.5.0.md). Not bigwrite. After every drive, the laptop runs each partition's own
checker read-only, matches every fixture against the manifest, and compares the volume with its
baseline.

## Results

| | Drive 1 | Drive 2/2 | Drive 3 | Drive 4 | Drive 5/1 |
|---|---|---|---|---|---|
| Pixel 7 Pro | 10/10 · CLEAN | 10/10 · CLEAN | 10/10 · CLEAN | 10/10 · CLEAN | 10/10 · host 9/10¹ · **unlock time FAILED**² |

The read-only partitions (APFS, ext2 and ext3) run the read sections and fixtures, and skip the
writes by design. Every other partition passed write verify, unaligned and correctness, and every
partition matched all of its fixtures.

1. **p8, plain FAT32: the FAT32 dirty bit.** Android's vold mounts plain FAT32 at plug-in and
   leaves boot-sector byte 0x41 set. Only that byte and FSInfo's free count differ from the
   baseline, `fsck.fat -n` reports nothing else, and all 20027 fixtures matched. It is the same
   cause as Drive 5 p8 on the Pixel in 0.5.0.
2. **VeraCrypt unlocks are slower than in 0.5.0, and this ships knowingly.** Request to mount on
   the same phone and drive, against the 0.5.0 run (`cae0e9e`):

   | Partition | 0.5.0 | 0.5.1 |
   |---|---|---|
   | AES-Twofish-Serpent, Argon2id, PIM 0 | 118 s | 217 s |
   | Serpent-Twofish-AES, Argon2id, PIM 1 | 10 s | 17 s |
   | Twofish, SHA-512, PIM 0 | 12 s | 21 s |
   | AES-Twofish, Argon2id, PIM 1 | 9 s | 17 s |
   | Serpent-AES, SHA-512, PIM 1 | 5 s | 5 s |
   | Twofish-Serpent, Argon2id, PIM 31 | 732 s | 1399 s |

   That fails the rule that a 5% median regression in unlock time fails a run. The likely cause is
   the hidden volume support: after each failed standard header, the app now tries the hidden
   header too, so a request on this drive runs 11 key derivations where 0.5.0 ran 6. This is not
   proven yet. When the standard header opens on the first try, no hidden header is tried. The
   owner decided to fix it after 0.5.1. The phone's CPU clocks were also lower during this run.

**LUKS2 unlock, the reason for this release:** on the Pixel 7 Pro, same drive, a LUKS2 unlock took
4.9 s before the regression, 10.5 s on 0.5.0, and 5.3 s with the fix.
